# SPK-EFFA-Site-Monitor

Публичный технический мониторинг сайта [spk-effa.ru](https://spk-effa.ru/). Только **read-only** HTTP(S)-запросы к публичным страницам; без авторизации, заявок, заказов, отправки форм или изменения сайта. **TinyFish.ai не используется.**

## Расписание

Каждый день в **18:00 по Уфе (13:00 UTC)**, плюс ручной запуск через **Actions → Daily public-site QA → Run workflow**. GitHub может запускать задачи с задержкой. Стандартные GitHub-hosted runners бесплатны для публичных репозиториев (с учётом действующих правил GitHub). Хранение артефактов и кэша имеет отдельные квоты; этот workflow не загружает артефакты и не использует кэш. GitHub может отключить расписание публичного репозитория после 60 дней без активности.

## Проверки

- DNS, сертификат TLS и HTTP-ответы главной страницы и каталогов `/blank/`, `/ognezaschita/`, `/veksa/`.
- Две карточки товара на каждом прогоне (ротация); название, заголовок, описание, изображения, alt, признаки характеристик, цены и CTA. Изображения с lazy loading не считаются сломанными лишь потому, что не попали в экран.
- Публичные внутренние (до 65) и внешние (до 10) ссылки с проверкой редиректов. URL с query-параметрами, приватные IP и пути потенциальных действий пропускаются.
- PDF (до 12): HTTP, `Content-Type`, PDF-сигнатура, возможность прочитать документ и число страниц.
- Для контрольного товара **ЭФФА А-01** — ровно два поисковых запроса в каждом из **Bing, Google и Яндекс** (6 запросов за прогон): `"ЭФФА А-01"` и `"ЭФФА А-01" spk-effa.ru`. Позиции фиксируются только при распознавании органической выдачи, без рекламных результатов. При CAPTCHA/блокировке позиции помечаются как непроверенные. При недоступности любого поисковика его позиции отмечаются как непроверенные и не заменяются данными другого поисковика. Для Google фиксируются `hl=ru, gl=ru`; для Яндекса регион Уфа (`lr=172`); Bing — `setlang=ru-RU`.
- Ежедневное сравнение с предыдущим `reports/latest.json`; непроверенные SERP не сравниваются.

## Отчёты

`reports/latest.md` — текущий краткий отчёт, `reports/latest.json` — машинный отчёт, `reports/history/YYYY-MM-DD.json` — история. В публичные отчёты попадают только статусы, безопасные URL без query-строк, технические метаданные, названия публичных товаров и найденные позиции. **Нет сырых HTML/PDF, содержимого alt-атрибутов, содержимого форм, cookies, паролей, токенов или персональных данных.**

## Безопасность

Для сохранения отчётов используется **встроенный временный `GITHUB_TOKEN` GitHub Actions**, не персональный токен и не ключ в репозитории. Он автоматически передаётся GitHub и **не записывается в отчёты**. Workflow запрашивает право `contents: write` только для публикации отчётов. Не добавляйте собственные ключи, `.env`, секреты или логи с учётными данными в репозиторий. Содержимое отчётов публично; при необходимости сделать сами отчёты закрытыми следует перейти на приватное хранение артефактов/другой репозиторий.

**Важно:** обнаружение проблемы из среды GitHub Actions не доказывает глобальную недоступность сайта; DNS/сетевые ошибки помечаются как `unverified`. HTTP 4xx/5xx отмечаются как ошибки конкретной проверки. Проверка не охватывает все страницы, все PDF и все изображения на каждом запуске.

## Локальная проверка

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest -q
python -m monitor.audit
```

## Разрешения GitHub

Если публикация отчётов не проходит из-за 403, проверьте **Settings → Actions → General → Workflow permissions**. Для этого workflow требуется разрешение чтения и записи содержимого репозитория; никаких персональных токенов не требуется.
